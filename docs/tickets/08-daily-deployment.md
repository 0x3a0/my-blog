# 08：每天自动同步并完整发布到 GitHub Pages

状态：待确认，尚未发布。对应规格用户故事：21、22。

## Parent

[语雀同步、文章详情与按年归档规格 #1](https://github.com/0x3a0/my-blog/issues/1)。

## What to build

项目默认分支上的自动任务每天北京时间 06:00 计划同步语雀并发布完整博客。作者后续只需在语雀写作和选定内容；任务失败时线上保留上次网站。

## Acceptance criteria

- [ ] 在现有 GitHub Pages 流程中接通每日北京时间 06:00 的计划触发，实际开始和完成时间单独记录，允许调度排队。
- [ ] 自动任务使用同一次候选结果完成语雀同步、校验、静态构建及部署，只有完整成功才部署；失败任务不会替换线上站点。
- [ ] 配置一个知识库与博客发布分组，读取凭据只注入任务执行环境，不进入仓库正文、日志、静态产物或测试返回。
- [ ] 默认分支具有可执行的项目代码，GitHub Pages 与所需语雀读取配置可用；代码交付、Pages 设置与凭据注入的实际前提被验证和记录，不假设本地目录已经推送。
- [ ] 首次完整验证：首页最新五篇、blogs 按年归档、详情、元数据、匿名图片和子路径均正确；随后验证改标题、保存修改及移出分组。
- [ ] 通过一次失败运行证明旧线上版本保留，再通过成功运行证明更新与撤回统一生效；常规自动测试仍使用可控去敏返回，不依赖生产账号。
- [ ] 沿用现有技术栈、包管理与部署约定；运维说明包含配置方式、同步报告及失败排查入口，并以短文档组织。
- [ ] 所有前置任务的验收通过后再启用每日线上同步，不将功能完成等同于计划任务已成功触发。

## Blocked by

6：通过 Header 的 blogs 浏览按年归档；7：让更新与撤回只在整次同步成功后生效。
