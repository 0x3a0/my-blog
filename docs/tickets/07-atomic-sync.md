# 07：让更新与撤回只在整次同步成功后生效

状态：待确认，尚未发布。对应规格用户故事：35、36、38。

## Parent

[语雀同步、文章详情与按年归档规格 #1](https://github.com/0x3a0/my-blog/issues/1)。

## What to build

一次同步中的新增、修改、图片与撤回作为同一个候选结果处理。任一文章、元数据、资源或构建失败时，读者继续访问上一次完整网站，不出现半次更新。

## Acceptance criteria

- [ ] 完整候选内容与资源在隔离输出中准备，经所有校验及真实静态构建成功后才成为可发布结果。
- [ ] 成功时统一生效新增、修改与撤回；失败时退出为失败且不替换上次完整内容、资源或可发布网站。
- [ ] 覆盖本次既有撤回又有其他文章失败的场景，验证没有部分更新、部分下架或提前删除旧资源。
- [ ] 接口异常、权限变化、分页未完成、元数据错误、普通正文转换失败、必需图片失败和构建失败均阻止整次提交。
- [ ] 完整成功的空集合允许正常撤回全部文章并生成真实空站点；与来源读取失败明确区分。
- [ ] 针对已存在的完整站点，使用可控语雀返回运行真实同步及静态构建，检查成功结果与失败后的文章、页面和图片仍完整一致；复用已确认的主要测试入口。
- [ ] 提供给后续自动发布流程的产物与成功状态明确，失败结果不能进入部署；已实现的列表、详情和资源使用同一候选快照。
