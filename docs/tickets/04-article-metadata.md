# 04：让语雀正文元数据控制博客摘要与分类

状态：待确认，尚未发布。对应规格用户故事：15、16、17、18、19、20、30、56。

## Parent

[语雀同步、文章详情与按年归档规格 #1](https://github.com/0x3a0/my-blog/issues/1)。

## What to build

作者可在语雀正文开头填写 description 与 category；同步后首页展示摘要与分类，详情正文去掉元数据。没有填写时按既定规则补齐，损坏元数据不会变成部分发布。

## Acceptance criteria

- [ ] 仅将正文开头的 YAML frontmatter 提取为元数据，并从最终可见正文移除；整段省略时正常导入。
- [ ] 标题始终取语雀文章标题，frontmatter 中的 title 不成为第二标题来源；分类使用 category，type 不作为分类。
- [ ] description 优先使用作者填写值，缺省时使用语雀摘要，再缺省时从移除元数据后的正文生成短摘要。
- [ ] category 缺省为“随笔”，博客发布分组及子分组名称不自动成为分类。
- [ ] 存在错误 YAML、未闭合分隔线、非映射结构或无效字段值时整次同步失败，保留上次完整结果。
- [ ] 最终首页与详情反映摘要、分类及唯一标题，正文不显示 frontmatter；不要求作者补写整段元数据。
- [ ] 通过真实同步与构建验证有效元数据、省略、摘要逐级回退、分类默认、重复标题字段和格式错误时的保留行为。
