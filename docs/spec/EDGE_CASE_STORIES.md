# 日期、正文与范围边界

61. 作为作者，我希望选定文章缺少 Published 时被明确指出，以便补齐日期后再同步。
62. 作为作者，我希望未来 Published 不阻止文章发布，以便日期只控制显示、排序和归档。
63. 作为作者，我希望 Published 的纯日期保持填写日，以便不因时区转换改变日期。
64. 作为读者，我希望带时间的 Published 按北京时间展示及归档，以便跨年边界一致。
65. 作为作者，我希望日期区间只使用起始日期，以便结束日期不改变博客规则。
66. 作为作者，我希望修改 Published 能更新排序与归档位置，以便在源文章中修正日期。
67. 作为作者，我希望 Tags 不自动变成 category，以便保留两者各自的整理用途。
68. 作为作者，我希望 AI custom autofill 不自动成为 description，以便摘要只取明确填写的属性。
69. 作为作者，我希望空分类和摘要不被写回 Notion，以便博客缺省展示不修改源文章。
70. 作为读者，我希望提示框转换为引用，以便保留其中的文字与基本结构。
71. 作为读者，我希望并排栏按顺序转为单栏，以便正文内容及阅读顺序保留。
72. 作为作者，我希望子页面不自动展开或发布，以便父文章的勾选不扩大公开范围。
73. 作为作者，我希望子页只有独立加入文章库并勾选后才发布，以便每篇文章分别授权。
74. 作为读者，我希望指向本次已同步文章的链接转为博客地址，以便在博客内继续阅读。
75. 作为读者，我希望其他 Notion 链接保留源地址，以便博客不生成不存在的文章入口。
76. 作为作者，我希望空正文允许同步并清空旧正文，以便已删除内容不会因回退而重新出现。
77. 作为读者，我希望空正文文章仍显示标题与属性，以便页面反映作者当前保存状态。
78. 作为维护者，我希望首版遇到范围外内容时明确失败，以便不静默丢掉公式或复杂嵌入等内容。
79. 作为读者，我希望可信空文章集合显示空状态，以便示例内容不会冒充真实文章。
80. 作为维护者，我希望撤回计划与其他失败同时出现时保留旧站点，以便失败不造成部分下架。
