# 测试方案

状态：用户已确认测试入口，尚未编写或运行功能测试。

## 主要 Seam

以“一次同步任务 → 候选内容 → 静态网站”为主要测试入口。测试调用真实的同步 Interface，并沿用真实的内容集合与构建流程；语雀读取 Adapter 使用可重放的返回，覆盖正常、分页、异常和权限变化。

检查最终文章、资源、页面、退出状态及旧站点是否保持完整；不 mock 内部 YAML 解析、排序或撤回函数，也不依赖内部调用顺序。修改内部组织后，外部行为不变的测试仍应通过。

## 模块与先例

验证同步 Module 的公开 Interface 及其输出，随后检查实际生成的详情页、归档、首页入口和 Header。现有项目有类型检查与静态构建流程，但没有已配置的测试脚本或可沿用的正式测试套件。优先考虑现有 Node 运行环境的内置测试工具，测试运行方式在实现时确定。

## 真实验证与页面检查

首次接入使用真实代表文章验证读取契约；常规自动测试使用去除凭据与个人内容的固定返回，不依赖真实语雀账号或生产发布。

桌面与移动端检查归档参考布局、标题换行、正文目录、代码块、表格和图片。功能验收场景见[场景清单](./TEST_CASES.md)。
