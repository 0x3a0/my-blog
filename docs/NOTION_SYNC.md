# Notion 同步

- 使用官方 SDK，优先直接读取配置中的 My blog 数据源；只配置数据库 ID 时寻找唯一数据源。
- 每日北京时间 06:00 计划触发，完成时间受排队与构建影响。
- 仅发布 to-blog-site 勾选文章，更新最新保存的标题、属性和正文。
- 稳定页面身份决定地址；Published 作文章日期，最后编辑时间仅用于同步一致性检查。
- 撤回在下一次完整成功同步生效，见[发布边界](./ARTICLE_PUBLISHING.md)。

## 完整发布

读取、属性校验、转换、必需图片或构建任一失败，整次不发布，保留上次完整站点。

每次以本次完整成功查询的勾选集合生成全站，不读取上一版文章 ID，不逐篇确认旧文章缺失原因。正常完整空集合提交为空站点；接口失败、权限错误或查询不完整均停止发布。成功查询的可见集合变化按本次结果生效。

## 接入状态

入口为 `pnpm notion:sync`，一次完成全量读取、转换和真实 Astro 构建。候选暂存 `.cache/notion`，末次一致性检查通过后将文章移至 `src/content/blog`、图片移至 `public/article-assets`，完整站点保存到 `dist`。每次完整替换，不合并旧文章、旧图片或旧详情。

开发使用 Astro 默认的 `.astro` 缓存，可重新生成。同步不生成本地或线上发布清单，不依赖持久同步状态。临时候选用于失败保护，成功或正常失败后清理；回滚失败时保留恢复材料。

输出、文章及图片目录分别互斥，避免不同输出任务同时覆盖工作文件。任一目录替换失败时回滚已替换部分；图片资源按完整选定集合重建，撤回后的旧图片不混入新站点。生成正文和图片不提交 Git，CI 从 Notion 重建。Windows 短暂占用目录时有限重试，永久失败仍停止发布。

查询时直接筛选勾选文章，属性按页面一起读取，需要时补读单项属性，正文通过官方 Markdown 接口读取。Notion 扩展格式先规范化，文章链接、图片说明与持久图片替换共用一次 Markdown 解析和输出。

线上使用 `pnpm notion:publish`，先类型检查，再执行同一全量同步入口；不请求旧站点，首次部署与后续部署采用同一流程。

已验证一篇真实文章。分页、图片、特殊块及失败保护经过可控返回测试；真实图片、撤回和线上定时发布的剩余验收见[记录](./NOTION_ACCEPTANCE.md)。接口细节见[读取契约](./spec/API_CONTRACT.md)。
